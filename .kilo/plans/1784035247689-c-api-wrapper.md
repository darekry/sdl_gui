# C API Wrapper for SDL GUI

## Overview

Add a C-compatible API layer (`extern "C"`) to the existing C++ library. One library (`libsdl_gui.a`/`.so`), two headers:
- `dist/sdl_gui.h` — C API (`extern "C"`, opaque handles)
- `dist/sdl_gui.hpp` — existing C++ API (unchanged)

## Design Decisions (settled)

| Decision | Choice |
|----------|--------|
| Handle strategy | **Unified** — single `sdlgui_element_t` for all widgets, `get_type()` for runtime checks |
| SDL lifecycle | **Convenience wrapper** — `sdlgui_create("title", w, h, resizable)` handles SDL init internally |
| Element ownership | **Parent in create_*** — `create_*(gui, parent, ...)`. parent=NULL → top-level (auto-addElement). parent!=NULL → addChild to parent. GTK/Win32 pattern. No standalone add_element/add_child needed (deferred to Phase 2 for dynamic reparenting). |
| Theme/Style (Phase 1) | **Presets + per-element setters** — 4 presets (Win9x, Dark, Light, HighContrast) + `set_background_color`, `set_text_color`, `set_border`, `set_border_radius` |
| Scope (Phase 1) | **Core 7**: Button, Label, Panel, Slider, Checkbox, TextInput, ListView |
| Artifacts | One `.a`/`.so`, two headers. `sdl_gui_c_api.cpp` compiled into the same library |
| Naming | `sdlgui_` prefix, `snake_case` |

## Data Types

```c
// Opaque handles
typedef void* sdlgui_t;            // GUIManager + SDL context
typedef void* sdlgui_element_t;    // any widget (GUIElement*)

// Enums
typedef enum {
    SDLGUI_STATE_NORMAL   = 0,
    SDLGUI_STATE_HOVER    = 1,
    SDLGUI_STATE_PRESSED  = 2,
    SDLGUI_STATE_DISABLED = 3,
} sdlgui_element_state_t;

typedef enum {
    SDLGUI_ORIENTATION_HORIZONTAL = 0,
    SDLGUI_ORIENTATION_VERTICAL   = 1,
} sdlgui_orientation_t;

// Anchor struct (same memory layout as C++ Anchor)
typedef struct {
    float left;    // <0 = unset, 0.0-1.0 = percentage, >1.0 = pixels
    float top;
    float right;
    float bottom;
} sdlgui_anchor_t;

// Callback types
typedef void (*sdlgui_callback_t)(sdlgui_element_t element, void* userdata);
typedef void (*sdlgui_bool_callback_t)(sdlgui_element_t element, int value, void* userdata);
typedef void (*sdlgui_size_callback_t)(sdlgui_element_t element, size_t row, void* userdata);
```

## Phase 0: Infrastructure (blocking prerequisite)

### 0.1 Skeleton files

### 0.2 Context lifecycle (convenience wrapper)
```c
sdlgui_t sdlgui_create(const char* title, int width, int height, int resizable);
void     sdlgui_destroy(sdlgui_t gui);
```
Internally: `SDLApp` (creates window+renderer) + `GUIManager` + auto-applies `Theme::createDefaultTheme()` (Win9x).
`sdlgui_destroy()` tears down in reverse order: GUIManager → renderer → window → TTF_Quit → SDL_Quit.

## Implementation Details

### Internal structure
```cpp
struct CContext {
    SDLApp app;
    GUIManager guiManager;
};
// sdlgui_t = CContext*

static CContext* unwrap_ctx(sdlgui_t gui) { return static_cast<CContext*>(gui); }
static GUIElement* unwrap_elem(sdlgui_element_t e) { return static_cast<GUIElement*>(e); }
static sdlgui_element_t wrap_elem(GUIElement* e) { return e; }
```

### create_* implementation pattern
```cpp
extern "C" {

sdlgui_element_t sdlgui_button_create(sdlgui_t gui, sdlgui_element_t parent,
                                       int x, int y, int w, int h, const char* label) {
    auto* ctx = unwrap_ctx(gui);
    std::string_view label_sv(label ? label : "");
    auto btn = std::make_unique<Button>(ctx->guiManager, x, y, w, h, label_sv);
    auto* raw = btn.get();

    if (parent) {
        auto* p = unwrap_elem(parent);
        p->addChild(std::move(btn));
    } else {
        ctx->guiManager.addElement(std::move(btn));
    }
    return wrap_elem(raw);
}

void sdlgui_button_set_on_click(sdlgui_element_t e, sdlgui_callback_t cb, void* userdata) {
    auto* btn = static_cast<Button*>(unwarp_elem(e));
    btn->setOnClickCallback([cb, userdata](GUIElement* elem) {
        if (cb) cb(wrap_elem(elem), userdata);
    });
}

} // extern "C"
```

### Callback lifetime
- `userdata` pointer stored in lambda capture — caller responsible for lifetime
- Callbacks fire as long as the element is alive (checked by C++ internals)
- No deregister function needed — element destruction clears `std::function`

### Memory model
- Elements owned by GUIManager or parent (via `unique_ptr`)
- C handles are raw pointers to `GUIElement*`
- A handle becomes dangling after `markForDeletion()` + `cleanup()`, or parent destruction
- C user must not use a handle after `sdlgui_cleanup()` or parent destruction
- Document clearly in `sdl_gui.h` comments

### String return conventions
Three cases, documented per function in `sdl_gui.h`:
- **Returns `const std::string&`** (Label::getText, TextInput::getText): `.c_str()` stable until next modification of the element
- **Returns `std::string_view`** (ListView::getItem): `.data()` points to internal `std::string` storage, valid until item is modified/removed
- **Callbacks receiving text**: `const char*` valid only during callback execution; `strdup()` if needed later

## Risks & Mitigations

| Risk | Mitigation |
|------|-----------|
| `std::string` ownership in callbacks (strings passed to C callbacks may dangle) | Document that `const char*` in callbacks is valid only during callback execution; user must `strdup()` if they need to keep it |
| Handle becomes dangling after element deletion | Document the `markForDeletion`/`cleanup` lifecycle. Consider adding `sdlgui_element_is_valid()` helper in Phase 2 |
| `sdlgui_element_t` can be cast to wrong widget type (e.g. `sdlgui_slider_get_value` on a Button) | `assert()` in debug builds via `getComponentType()` check (e.g. `strcmp(get_type(e), "Slider") == 0`); graceful no-op in release |
| SDL event handling differs between C and C++ (reference vs pointer) | C API takes `const SDL_Event*`, internal casts to `const SDL_Event&`. Trivial. |
| C examples need SDL3 headers/library installed | Same requirements as C++ examples — already documented |
| Pure C compilation of header fails (C++ syntax leaks) | Smoke test in release script compiles with `gcc` to catch early |
| `ListView::getItem` returns `string_view` — `.data()` not null-terminated per standard | Points into `std::string` internal storage which IS null-terminated. Safe in practice. Document the edge case. |
